# nf-core/scalpel: Output

## Introduction

This document describes the output produced by the pipeline.

The directories listed below will be created in the results directory after the pipeline has finished. All paths are relative to the top-level results directory.

## Pipeline overview

The pipeline is built using [Nextflow](https://www.nextflow.io/) and processes data using the following steps:

- [Main results](#main-results) - isoform count matrices & differential isoform usage
- [Intermediate files](#intermediate-files) - per-step outputs
- [Pipeline information](#pipeline-information) - Report metrics generated during the workflow execution

### Main results

<details markdown="1">
<summary>Output files</summary>

- `dge/<sample>_iDGE/`: isoform x cell count matrix (iDGE) per sample, sparse 10x format
  (`matrix.mtx.gz`, `features.tsv.gz`, `barcodes.tsv.gz`). Features are `gene***transcript`.
  Read with `Seurat::Read10X("<sample>_iDGE", gene.column = 1)`.
- `differential/iDGE_seurat.RDS`: Seurat object of all samples (cells named `<sample>_<barcode>`,
  metadata `orig.ident` = sample, `Barcodes` = cell barcode, `Clusters`).
- `filtered_bams/<sample>_filtered.bam(.bai)`: reads kept by SCALPEL after all filtering steps
  (e.g. coverage visualization of the quantified isoforms).
- `pipeline_info/nf_core_scalpel_software_versions.yml`: versions of all tools & R packages used.
- `differential/DIU_table.csv`: differential isoform usage (tab-separated) between clusters
  (`--clusters`) or samples, one row per isoform and comparison (`comparison`, `group1`, `group2`;
  more than 2 groups: each group vs `rest`):
  - aggregated counts per group (one column per group), `counts.group1/2`, isoform usage
    `PU.group1/2` and its change `delta_PU` (group1 - group2);
  - isoform 3' end (`strand`, `three_end`), distance to the most proximal 3' end of the gene
    (`dist_3end`, `end_rank` 1 = most proximal) and gene 3' end shift `delta_3end` (nt; > 0: group1
    uses more distal 3' ends, i.e. longer 3' UTRs);
  - filters `thr.abund` (< 5% of the gene in both groups, not tested) and `thr.var` (usage change
    < `--diu_min_delta`), gene `statistic` (X2), `p.value` (`--diu_test`), `p.value.adjusted` (BH
    per gene), `max_delta_PU`, `significant`, `test` and `n_perm` (permutations run).

</details>

### Intermediate files

<details markdown="1">
<summary>Output files</summary>

- `salmon/`: pseudobulk salmon quantification per sample.
- `transcript/`, `isoform/`: per-chromosome annotation with averaged TPM and selected isoforms
  (`isoform/*.annots.gz`, reusable with `--isoform_annotation`).
- `ip_reference/ip_reference.track.gz`: internal priming reference generated from `--genome`
  (only without `--ip_reference`), reusable with `--ip_reference`.
- `bed/<sample>/`, `reads/`, `ip/`: reads per chromosome (PCR duplicates removed), reads mapped to isoforms, internal priming filtered reads.
- `probability/<sample>.prob|.pdf`: read distance distribution to the 3' ends.
- `fragment/`, `cell/`, `em/`: fragment probabilities, cell chunks and EM isoform abundances.

</details>


### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.dot`/`pipeline_dag.svg`.
  - Reports generated by the pipeline: `pipeline_report.html`, `pipeline_report.txt` and `software_versions.yml`. The `pipeline_report*` files will only be present if the `--email` / `--email_on_fail` parameter's are used when running the pipeline.
  - Reformatted samplesheet files used as input to the pipeline: `samplesheet.valid.csv`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://www.nextflow.io/docs/latest/tracing.html) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
